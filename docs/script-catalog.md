# 推荐脚本库（可选脚本）· 设计与选型

> 版本 **v1** · 范围 Android 移动端 · 对应代码 `ScriptCatalog` / `ScriptInstaller` / `MainActivity` 的「浏览推荐脚本」面板
> 一句话：**清单随包内置，但一条都不装**——用户点哪条才去 Greasy Fork 下哪条。

---

## 1. 它跟「内置脚本」是两回事

项目里原本已经有用户脚本能力，但那是 {@code BuiltinScripts} 的语义：**随包发布 + 首次启动自动装上**（目前一条：「网页限制解除」）。本功能反过来。

| | `BuiltinScripts`（已有） | `ScriptCatalog`（本次新增） |
|---|---|---|
| 脚本本体 | 打进 APK 的 `assets/` | **不入包**，只存下载地址 |
| 默认行为 | **首次启动自动装上并启用** | **一条都不装**，用户点哪条装哪条 |
| 数量上限 | 极少（每加一条都要替全体用户做决定） | 可以多，用户自己筛 |
| 关键词 | 播种（seed） | 目录（catalog） |

两者默认行为正好相反，所以**没有合并成一个类**。合并之后这两种语义会挤在同一个 `MANIFEST` 上，迟早被改错一处——而改错的方向恰好是「把可选的东西变成默认装上」。

---

## 2. 为什么脚本本体不入包

三条理由，按重要性排：

1. **版权**。随包分发第三方脚本要过许可这道关。「网页限制解除」能内置，是因为它恰好是 **LGPLv3**（明确允许再分发），而且许可证全文也随包放了。但 Greasy Fork 上大量脚本没有声明许可、或只写「保留所有权利」——那些**不能**打进 APK。只存地址就绕开了这个问题：下载发生在用户自己的设备上，为的是他自己的使用。
2. **体积**。本包 release 实现前是 **386KB**，实现本功能后实测 **407KB**（净增约 21KB）。这 21KB 正是「只存地址」换来的 —— 如果随包内置那 8 条脚本，增量会大一个量级。
3. **时效**。脚本作者随时更新，随包的那份从发版起就冻结了。

## 3. 入选门槛（两道）

### 第一道（硬门槛）：引擎跑不跑得起来

本引擎不提供任何 `GM_*` 特权接口，也做不到 `@run-at document-start`。所以依赖下列能力的脚本**一律不入清单**：

| 依赖 | 用途 | 本引擎 |
|---|---|---|
| `GM_xmlhttpRequest` | 跨域请求 | ❌ 不提供 |
| `GM_setValue` / `GM_getValue` | 持久化配置 | ❌ 不提供 |
| `GM_registerMenuCommand` | 脚本菜单 | ❌ 不提供 |
| `GM_addStyle` | 注入 CSS | ❌ 不提供 |
| `@run-at document-start` | 文档创建前注入 | ❌ 只能 `document-end` |

**为什么不入清单而不是「装了再提示」**：装上只会静默失败——用户以为装了个好用的东西，实际什么都没发生，还怪浏览器有 bug。**那比不提供更糟。**

### 第二道：口碑

安装量与评分。

### 3.1 因第一道门槛被排除的脚本（真实例子）

| 脚本 | 安装量 | 排除原因 |
|---|---|---|
| AC-Baidu 净化搜索 | 约 342 万（Greasy Fork 总第一） | 依赖 `GM_xmlhttpRequest` + `GM_setValue` |
| 网页翻译器（573432） | 3,495 | 声明了 5 个 GM 接口 |
| 知乎增强（419081） | 很高 | 功能开关挂在油猴右上角菜单上（`GM_registerMenuCommand`）。它默认全开、能跑一部分，但**「关不掉」意味着用户遇到误伤时没有退路** |
| Chrome Translator（545629） | — | 依赖 Chrome ≥138 的原生翻译 API，WebView 里不可用 |

> **翻译类脚本是重灾区**：几乎全都靠 `GM_xmlhttpRequest` 调翻译接口。能被第一道门槛筛掉大半——最终留下的是**以弹窗/面板方式调外部词典页**的那一类。

## 5. 安装流程

```
点「安装」→ ScriptInstaller 下载 → UserScript.parse 解析
    → 能力检测（@grant / 无头脚本）→ 弹确认框列出检测结果
    → 用户点「安装」→ store.saveScript 落盘
```

**关键：下载回来的第一件事不是写库，而是把检测结果摆给用户看。** 用户点了确认才落盘 —— 这是 `ScriptInstaller` 只负责「取回来 + 验一遍」、不负责落盘的原因。

### 5.1 必须防住的一条：HTML 被误装成全站脚本

`UserScript.parse` 对**没有元数据头**的文本会兜底成 `@match *://*/*`（所有网站都运行）。于是：

> 一张 HTML 错误页（脚本已下架、地址被重定向到首页）
> → 被当成「无头脚本」
> → 装成一个**全站脚本**，在用户的每个网页上跑。

所以 `ScriptInstaller` 在进 `parse` 之前先做两道判断：

1. **Content-Type 是 `text/html`** → 拒绝，并说明「这条脚本可能已下架」；
2. **正文 trim 后以 `<!doctype` 或 `<html` 开头** → 拒绝。

只认**开头**，不认「包含」——往页面插元素的正常脚本正文里当然有 HTML 字符串，用「包含」判断会把它们误伤成网页，那是另一种错。

### 5.2 无头脚本要给提示

真的没有元数据头（而不是网页）时，不拒绝，但 `Result.headless` 会置位，确认框里明确写「它会被当成『所有网站都运行』」。用户有权在装之前知道。

## 6. 「未确认」是什么意思

清单里的 `verified` 字段表示**该脚本的 `@grant` 声明是否经过人工核对**。

清单是在无网络环境下整理的，多数条目无法在包内逐个验证，所以它们标 `未确认`。**这不是「大概不能用」，是「没确认过」**——界面上这两种状态必须分开显示（已确认用强调色、未确认用中性色），不能让用户把「没核对过」读成「不推荐」。

**真正的兜底在安装那一刻**：`ScriptInstaller` 会把下载到的脚本交给 `UserScript.parse`，那里读出的是**真实的** `@grant`，并逐项列出来。

> 也就是说，**未确认项会在用户点下安装的那一秒变成已验证**。这比在清单里猜准确得多，也不必让发布者预先验证每一条。

## 7. 怎么加一条新脚本

1. 在 `ScriptCatalog.ALL` 里加一条 `it(...)`，**参数共 10 个**：`key, category, name, author, license, desc, scriptId, fileName, verified, caution`（少一个会编译不过，这个辅助方法不校验个数）。
2. `scriptId` 是 Greasy Fork 脚本页 `/scripts/{id}` 里的那个数字。
3. `fileName` 填直链路径里的文件名段，通常是脚本的 `@name`。中文没关系，`pathEncode` 会逐字节编码。
4. **先确认脚本没有依赖 §3 里那些 GM 接口**。查不了就填 `verified=false` 并把 `caution` 写清楚。
5. 跑 `ScriptCatalogTest`——它会检查 key 唯一、字段非空、中文编码、来源反查等。

### 7.1 一个容易写错的地方：URL 编码

`installUrl` 用 `pathEncode` 而**不是** `URLEncoder.encode`。后者是为表单设计的，会把空格编成 `+`，而 `+` 在 URL 路径里是**字面加号**——中文脚本名一旦含空格，拼出来的地址就指向一个不存在的文件，表现为 404 且看不出原因。

`ScriptCatalogTest.空格编成百分号而不是加号` 专门钉住这一点。

## 8. 已知限制与待验证项

| 项 | 说明 |
|---|---|
| 直链格式未实测 | 用的是 `https://update.greasyfork.org/scripts/{id}/{name}.user.js`。当前环境访问 Greasy Fork 被网络策略拦截（HTTP 502），**该格式需在能联网的环境实测确认**。若格式有出入，只需改 `installUrl` 一处。 |
| 多数条目 `verified=false` | 同上原因，无法在包内验证 `@grant`。安装时的自动检测是兜底。 |
| 依赖第三方站点 | Greasy Fork 不可访问时功能不可用（会给出「域名解析失败：可能当前网络无法访问 Greasy Fork」）。 |
| 不做自动更新 | 装完之后不再检查上游更新。脚本更新需要用户自行卸载重装。 |
| `window.open` 型脚本 | 「Translate」以 `window.open` 弹窗展示结果，而 WebView 默认拦截 `window.open`，可能需要额外配置才能生效——已写进该条的 `caution`。 |
