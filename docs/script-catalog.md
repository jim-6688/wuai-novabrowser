# 推荐脚本库（可选脚本）· 设计与选型

> 版本 **v2** · 范围 Android 移动端 · 对应代码 `ScriptCatalog` / `ScriptInstaller` / `MainActivity` 的「浏览推荐脚本」面板
> 一句话：**清单随包内置、其中许可允许的那几条正文也随包内置；但一条都不自动装**——用户点哪条才装哪条。

---

## 1. 它跟「内置脚本」是两回事

项目里原本已经有用户脚本能力，但那是 `BuiltinScripts` 的语义：**随包发布 + 首次启动自动装上**（目前一条：「网页限制解除」）。本功能反过来。

| | `BuiltinScripts`（已有） | `ScriptCatalog`（本功能） |
|---|---|---|
| 脚本本体 | 打进 APK 的 `assets/user-scripts/` | 许可允许的进 `assets/user-scripts/catalog/`，其余只存下载地址 |
| 默认行为 | **首次启动自动装上并启用** | **一条都不装**，用户点哪条装哪条 |
| 数量上限 | 极少（每加一条都要替全体用户做决定） | 可以多，用户自己筛 |
| 关键词 | 播种（seed） | 目录（catalog） |

两者默认行为正好相反，所以**没有合并成一个类**。合并之后这两种语义会挤在同一个 `MANIFEST` 上，迟早被改错一处——而改错的方向恰好是「把可选的东西变成默认装上」。

---

## 2. 为什么源从 Greasy Fork 换成了脚本猫

v1 用的是 `update.greasyfork.org`。实测结论：**那个域名在国内网络下整条链路都断了。**

| 目标 | 直连结果（同一台机器，不走代理） |
|---|---|
| `update.greasyfork.org` | 12 秒无响应，`http=000` |
| `scriptcat.org` | 307，2.9 秒完成 |

再往上看一层 DNS：系统解析器（`dialdns.bta.net.cn`）把 `greasyfork.org` 解析到 `2a03:2880:f136:83:face:b00c:...`——这是 Facebook 的 IPv6 段，是典型的**污染返回**；解析出的 IPv4 也是停放地址。换真实 IP 直连同样全部超时。

所以这不是「有时候慢」的地址，是**恒定不可达**。表现是清单看得见、「安装」按钮点得动、然后每次都失败——失败原因写得再准确也没用，因为用户除了放弃没有别的选择。

换成脚本猫的理由是三条叠在一起：

1. **可达**。见上表。一个装不上的库，条目选得再好也是零。
2. **中文圈的口碑数据是真的**。脚本猫公开每条脚本的累计安装量，「为什么是这几条」有据可查，不是凭印象挑。
3. **它能自己讲清授权**。条目带 `@license`，于是「哪几条能随包分发、哪几条只能在线装」有事实依据，不用靠猜。

---

## 3. 为什么有的内置、有的只在线

换源解决了「有网时能装」，但没解决「没网时一条都装不上」。所以能不能随包分发，取决于脚本自己的许可：

| | 条件 | 安装路径 |
|---|---|---|
| **已内置** | `@license` 明确允许再分发（MIT / GPL-3.0 等） | 从 `assets/user-scripts/catalog/` 读，**全程不碰网络** |
| **需联网** | 没写许可，或写了「保留所有权利」 | 从 `scriptcat.org` 现下 |

**「它没写许可」和「它允许我分发」是两件事。** 前者不进包不是偷懒，是授权问题。

内置脚本的正文**逐字节保持上游原样**：改一个字符，`ScriptCatalog` 里那条 sha256 追溯断言就断了，而「这份内置脚本到底是不是我们审计过的那一份」将无从回答。许可与署名集中写在 `assets/user-scripts/catalog/LICENSE-THIRD-PARTY.txt`，GPL-3.0 全文另放 `LICENSE-GPL-3.0.txt`。

## 4. 入选门槛（三道）

### 第一道（硬门槛）：引擎跑不跑得起来

本引擎的 `GM_` 支持集只有 `GmShim.SUPPORTED` 那六项（`GM_addStyle` / `GM_addElement` / `GM_log` / `GM_info` / `GM` / `unsafeWindow`），且做不到 `@run-at document-start`（原因见 `UserScript` 类注释）。所以依赖下列能力的脚本**一律不入清单**：

| 依赖 | 用途 | 本引擎 |
|---|---|---|
| `GM_xmlhttpRequest` | 跨域请求 | ❌ 不提供 |
| `GM_setValue` / `GM_getValue` | 持久化配置 | ❌ 不提供 |
| `GM_registerMenuCommand` | 脚本菜单 | ❌ 不提供 |
| `@run-at document-start` | 文档创建前注入 | ⚠️ 只能 `document-end` |

**为什么不入清单而不是「装了再提示」**：装上只会静默失败——用户以为装了个好用的东西，实际什么都没发生，还怪浏览器有 bug。**那比不提供更糟。**

每条的 `@grant` 记在 `ScriptCatalog.Item.grants` 里，由 `ScriptCatalogTest.每条脚本声明的权限引擎都得支持` 逐条对着 `GmShim.SUPPORTED` 核。这条不是风格偏好，是这份清单唯一能自证「选品没错」的地方。

> 注：`GM_` 支持集在 v1 之后扩过一轮（`GM_addStyle` / `GM_addElement` / `GM_log` / `GM_info` / `GM` / `unsafeWindow` 现在是有的），所以 v1 文档里那张「全部 ❌」的表已经作废。

### 第二道：口碑

安装量。清单里每条都标了整理时的读数，也是界面上那行来源的一部分。

### 第三道：不碰灰产

脚本猫上安装量最高的那批里，相当一部分是 VIP 视频解析、刷课、爬取付费内容一类。它们不是「技术上有问题」，是**不该被一个浏览器作为推荐内容推给用户**。这一类整体排除，不因为安装量高就破例。

## 6. 安装流程

两条路径，最终汇到同一个确认框：

```
已内置：store.readAssetText(asset) → ScriptInstaller.parseBundled
需联网：ScriptInstaller.fetch → HTTP GET scriptcat.org → ScriptInstaller.parseDownloaded
    ↓
UserScript.parse 解析 → 能力检测（@grant / 无头脚本）
    → 弹确认框列出检测结果（范围只列前三条，避免地址墙）
    → 用户点「安装」→ store.saveScript 落盘
```

**关键：取回来的第一件事不是写库，而是把检测结果摆给用户看。** 用户点了确认才落盘——这是 `ScriptInstaller` 只负责「取回来 + 验一遍」、不负责落盘的原因。

### 6.1 必须防住的一条：HTML 被误装成全站脚本

`UserScript.parse` 对**没有元数据头**的文本会兜底成 `@match *://*/*`（所有网站都运行）。于是：

> 一张 HTML 错误页（脚本已下架、地址被重定向到首页）
> → 被当成「无头脚本」
> → 装成一个**全站脚本**，在用户的每个网页上跑。

所以进 `parse` 之前先做两道判断：

1. **Content-Type 是 `text/html`** → 拒绝，并说明「这条脚本可能已下架」；
2. **正文 trim 后以 `<!doctype` 或 `<html` 开头** → 拒绝。

只认**开头**，不认「包含」——往页面插元素的正常脚本正文里当然有 HTML 字符串，用「包含」判断会把它们误伤成网页，那是另一种错。

### 6.2 来源必须挂回结果上

`parseDownloaded` 返回的是一个**新** `Result`，所以线上路径在它返回之后要把 `origin` 补上。漏掉的后果不是「来源那行空着」这么轻：脚本落盘时 origin 为空 → `ScriptCatalog.fromOrigin` 反查不到 → 装完之后清单里那条**仍然显示「安装」**，再点一次就装出第二份。

内置路径同理，由 `parseBundled` 挂——它本来就直到自己是哪一条。

### 6.3 内置脚本读不出来要说「打包问题」

内置脚本读不出来是**打包**问题。这时候报「网络错误」会让人对着网络猜一辈子，也猜不到这一层。`parseBundled` 失败时的文案因此明确指向安装包，并提示「可以先试标着『需联网』的那几条」。

## 7. 「已内置 / 需联网」徽章

清单条目右上角的徽章答的是**「这条现在装得上吗」**——比 v1 的「已确认 / 未确认」更该被一眼看到。

- 「已内置」用强调色：断网、飞行模式、域名被墙都装得上。
- 「需联网」用中性色：那几条的许可没允许随包分发，只能现下。

v1 的 `verified` 字段已经删掉：现在每条脚本的 `@grant` 都是选品时逐条核过的（并写成了断言），再挂一个「核过没核过」的布尔反而是个假信息源。

## 8. 怎么加一条新脚本

1. 在 `ScriptCatalog.ALL` 里加一条。用 `bundled(...)` 还是 `online(...)` 取决于许可——**没写许可或写了「保留所有权利」的一律 `online`**。
2. 参数：`key, category, name, author, license, desc, scriptId, fileName, installs, grants, [sha256,] caution`。`bundled` 多一个 `sha256` 参数。
3. `scriptId` 是脚本猫展示页 `/script-show-page/{id}` 里的那个数字。
4. `fileName` 填直链路径里的文件名段，通常是脚本的 `@name`。中文、表情、竖线都没关系，`pathEncode` 会逐字节编码。
5. `grants` 填脚本真实声明的 `@grant`（`none` 不要填）。**先跑 §4 第一道门槛**：只要有一项不在 `GmShim.SUPPORTED` 里就不该进来。
6. 内置的话：把正文放进 `assets/user-scripts/catalog/{key}.user.js`，`sha256sum` 出来填上去，并在 `LICENSE-THIRD-PARTY.txt` 里加一段署名，正文**不要改一个字符**。
7. 跑 `ScriptCatalogTest` + `BuiltinScriptsTest`。

### 8.1 一个容易写错的地方：URL 编码

`installUrl` 用 `pathEncode` 而**不是** `URLEncoder.encode`。后者是为表单设计的，会把空格编成 `+`，而 `+` 在 URL 路径里是**字面加号**——中文脚本名一旦含空格，拼出来的地址就指向一个不存在的文件，表现为 404 且看不出原因。

`ScriptCatalogTest.空格编成百分号而不是加号` 与 `.表情与竖线都能编掉` 专门钉住这一点。

## 9. 已知限制

| 项 | 说明 |
|---|---|
| 依赖第三方站点 | 脚本猫不可访问时，「需联网」那几条装不上（会给出「域名解析失败：当前网络可能无法访问脚本猫」）。「已内置」的那几条不受影响——这正是分两类的意义。 |
| 旧版本装上的脚本会被认成「未安装」 | v1 的 `origin` 是 Greasy Fork 地址，反查不到新清单。这是**对**的：那几条的来源与现在这套清单已经不是一回事了。 |
| 不做自动更新 | 装完之后不再检查上游更新。脚本更新需要用户自行卸载重装；内置的那几条要等下次发版。 |
| 内置脚本会随发版冻结 | 作者随时更新，随包的那份从发版起就停住了。要更新得重新审计、换正文、换 sha256。 |
| `@require` 不生效 | 引擎不取 `@require` 的外部依赖（`injectPlugins` 传 `null`）。清单里「全网视频倍速」声明了一个 `@require`，但正文没用它，所以无影响——**加新脚本时必须确认这一条**。 |
| 安装量会过期 | 清单里存的是整理时的读数。它不参与任何判断，只用来解释选品。 |

## 10. 测试

| 测试类 | 覆盖 |
|---|---|
| `ScriptCatalogTest` | key 唯一、字段非空、**权限支持集**、`none` 不混入、内置/未内置的 asset 与 sha256 形状、**内置正文与 sha256 一致**、内置资产真实存在、内置脚本解析出的 `@grant` 与清单记录一致、直链与展示页地址、**空格/中文/表情/竖线编码**、来源反查、分类非空 |
| `ScriptInstallerTest` | **HTML 拒绝**（含小写 doctype、前导空白）、空内容、正常脚本、GM 特权检出、`@grant none` 不误报、无头标记、正文含 HTML 字符串不误伤；**内置路径**：来源与 `local` 标记、与线上路径结果一致、坏文件时说「打包问题」、空清单项不抛 |

均为纯 JVM 单测，不依赖 Android 框架（与项目既有测试策略一致）。资产类断言读的是源码树里的 `src/main/assets`（测试工作目录就是模块目录）。
